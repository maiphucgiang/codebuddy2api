# WebUI 使用指南

[首页](../README.zh-CN.md) · [English](webui.md)

## 打开控制台

按[部署指南](deployment.zh-CN.md)启动网关后，打开 `http://127.0.0.1:8787/dashboard`，使用当前 API key 登录。源码安装需要先构建前端；Docker 镜像已包含。非本机访问请使用 HTTPS。

本地零配置首次启动会生成并保存默认 key，仅在终端显示一次；以后复用。显式空 key 锁定管理。更换生效 key 后需重新登录，并重新开始未完成的 OAuth 登录。

## 概览

可选 1/7/30/90 天与自动/小时/天粒度。自动粒度对一天用小时、其余用天；区间按 UTC 自然日。缺失的小时历史会标记缺失，不会用日总量反推；清理明细保留小时聚合。官方余额可能包含其他客户端的用量。

悬停或点按趋势图查看该时段的请求数、成功与失败数；方向键与 Home/End 可选点。缺失的小时段保持为空。

## 凭证管理

通过浏览器扫码登录添加账号——国内站（CN）、国际 WorkBuddy 或国际 CodeBuddy——导入 `.info`/ZIP 文件，或选定端点后粘贴最多 50 个刷新令牌：逐条换取并写入新凭证，账号信息保留企业租户。

- **运行状态：** 区分人工停用、凭证级认证熔断与模型级 429 冷却。停用保留文件；删除会移除文件，且须先解除模型绑定。导出保留安全的 UTF-8 文件名（否则用 `credential.info`/`credentials.zip`），内容为明文凭证，不要分享。
- **登录抽屉：** OAuth 入库成功后自动关闭抽屉并刷新列表。官方授权标签页保持 `noopener` 隔离，需手动关闭。失败状态保持可见；关闭抽屉即停止轮询。
- **维护操作：** 每行提供刷新 Token、签到与余额同步；批量签到与批量同步相互独立。同步只更新余额、目录与用量，不签到、不旅行、不领取试用。维护进行中返回 409；客户端超时不会取消服务端工作。
- **官方额度：** 详情抽屉单列一页，按套餐展示剩余、构成与逐段到期；类别按套餐名称归入套餐额度、活动奖励、新人权益、企业配额或其他。同步失败、快照超过一天、分页不全或含已过期段时会提示。卡片与列表的到期为积分最近到期，Token 有效期见同步状态。

### 自动化

自动签到与旅行按账号持久化并即时生效：国内个人账号默认开启，国际默认关闭；企业账号不参与成长中心，因此不旅行且不再显示上游 403。停用的账号不执行任何自动任务；未开始或未确认的活动不会触发领取。保存开关不会立即领取，也无法撤回已发出的请求；界面展示最近一次结果、部分完成与不确定状态。

- **成长任务：** 符合条件的国内个人账号在凭证抽屉中查看实时成长任务列表。每个任务有独立自动化开关（默认关闭）与一键手动执行；「全部执行」运行所有已开开关任务并附加幂等补领扫描，任务开关可复制到已选账号。`auto_growth` 总开关（默认开启）启用每小时接取/领取扫描，自身不启动行为链。手动执行可能通过真实对话消耗积分。
- **国内旅行** 有独立开关，即使签到已完成或关闭也按此开关执行。「查询状态」只读；「领取/派出」先领取到达奖励，复核空闲状态与每日上限，再选择当前上游位置。位置配置无效会停止派出。
- **首次领养（first_buddy）：** 勾选一个协议复选框，必要时通过一次真实 WorkBuddy 对话完成官方新手任务，然后领养并派出。无需单独接取任务。该对话最多请求 32 个输出 token，可能消耗积分；优先使用可用的零倍率模型，并在领养前核验官方完成状态。`CODEBUDDY2API_AUTO_ACCEPT_BUDDY=true` 在重启后预授权所有启用的国内账号（含后续导入）；默认关闭，自动后续仍受旅行开关控制，不执行其他奖励任务、付费开盒或试用领取。
- **国际 WorkBuddy 体验积分** 需在凭证行的抽屉中手动确认领取。「刷新领取状态」只读本地账本，不会发起领取。网络或落盘失败时先核实状态再重试；由环境变量驱动的自动领取已停用。

奖励领取与派出在发送前持久化预留。过期或失败的回读会在重启之间持续阻止重复写入，不按时间过期；只有状态被核对一致、或明确在发送前被取消/拒绝，预留才解除；首次领取的未确认发送只能通过读取核对，即使超过 24 小时或重启也不自动重放。确定未发出的对话可在设置或模型恢复后续发；不确定的对话绝不重复。授权与结果均有审计；自动旅行受阻时每个账号每天最多新增一条警告，不影响签到与余额同步。升级时请保留 `control.sqlite3`。

## 模型路由

添加独立映射，设置对外/上游 ID 与本地启停。绑定范围二选一：指定账号，或地域加可选产品过滤；切换模式会清除另一种绑定。候选不可用时绝不会回退到范围外账号。

- 「模型详情」按产品展示描述、能力状态、token 上限、推理选项与安全的原始元数据；有差异的字段分别保留。声明为只读参考，不构成原生能力或实测保证。路由预览使用草稿中的绑定范围。
- 国际目录共享并去重。继承的条目显示「共享目录来源」，可展开查看安全的原始声明；原生声明与共享引用始终可区分。
- 倍率列对「声明免费但上游实际扣费」的模型显示 `≈0.037x · 实测计费`，悬浮查看样本数；手填倍率显示 `· 手填`。「编辑规则 → 消费倍率」可按产品手填倍率，「一键探测倍率」在每个产品上发起一次约 8K token 的请求，区分真 0 倍率与实测计费；页头「一键检测倍率」对所有声明免费的模型执行同样探测。详见[实测计费与输出上限](advanced.zh-CN.md#实测计费与输出上限)。
- 最大输出列叠加 `scripts/probe_max_tokens.py` 的实测结果：红色 `32K ⚠ 钳制 12×` 表示静默钳制，绿色 `48K ✓` / `64K ↑` 表示与声称一致或更大，灰色 `≥40K` 为下界，`?` 为未测出。

## 日志

筛选请求并查看失败尝试。关闭详情或切换日志类型会取消进行中的详情加载。清理明细保留历史统计。

「清空全部日志与统计」不可恢复：输入对话框中的确认文字，并重新输入当前 API key。此操作不删除凭证与网关配置。

## 媒体生成

「媒体生成」页展示本地保存的生成结果：本地占用与容量上限、图片与视频数量、进行中与失败的视频任务。

- **资源库**按时间倒序列出资源，含模型、大小与剩余保留时长；卡片打开预览抽屉，可查看元数据、下载与两步删除。**视频任务**用绑定账号刷新进行中的任务，并把完成的视频链回资源库。**模型**为只读表格，展示媒体模型与当前可用的账号数。
- 只有配置了资源访问地址，图片才会落盘；未配置时以 base64 内联返回。视频始终保存到本地，配置地址后即可获得链接。
- **媒体设置**（`media_public_base_url`、`media_max_total_mb`、`media_ttl_hours`）分别设置公开链接前缀、容量（64–1048576 MB）与保留时长（1–8760 小时）。调小后会在下次写入或定时清理时淘汰最老的资源。资源同时经 `/v1/media/…` 公开读取，带不可变缓存头；见[媒体生成](clients.zh-CN.md#媒体生成)。

## 系统设置

编辑未锁定的选项；即时生效项立即应用，标记为重启的项需手动重启。被锁定的选项请在启动配置中修改；见[配置优先级](advanced.zh-CN.md#配置与-cli)。Dashboard 顶部横幅会列出仍由 `.env` 提供的运行参数；停止服务后用 `python3 converter.py config migrate` 迁移，或点一次“不再提醒”——两种方式之后都不再出现，即使 `.env` 又新增键。

- 「保留工具描述」默认关闭，对三种协议生效，与提示词压缩相互独立；见[工具元数据保留](advanced.zh-CN.md#工具元数据保留)。
- 「表外模型拦截」与「模型能力预检」开关位于「模型路由」顶部栏，默认开启；关闭能力预检只影响新请求，不影响元数据展示、国际图片消息合并与既有安全限制；见[模型声明](advanced.zh-CN.md#模型声明与图片兼容)。
- 「管理页额外信任来源」（`admin_allowed_origins`）用于修复 HTTPS 反代后的登录；见[管理 Origin 校验](advanced.zh-CN.md#管理-origin--csrf-开关)。

## 版本更新

「版本更新」页显示当前版本、部署方式与仓库地址，并列出 GitHub Releases 的稳定版本；选择版本（`/dashboard/updates/v<版本>`）可阅读其更新说明或跳转 GitHub。网关启动后及每 6 小时检查一次，侧栏在有新版本时显示提示；「检查更新」可手动刷新，60 秒内重复点击只返回缓存。无法访问 GitHub 时为进程设置 `HTTPS_PROXY`。

任何带发布包的版本都可一键安装：高于当前版本即更新，低于当前版本即回滚，流程相同。发布包解压、Git 工作区与容器部署都适用：

1. 下载所选版本的 `codebuddy2api-<版本>.tar.gz`，按 `SHA256SUMS` 与 GitHub API 返回的资产摘要校验；
2. 在程序目录内的 `.update/` 解压并校验结构与版本，拒绝越界路径；回滚时再确认目标版本声明的数据库结构版本能读取当前的 `control.sqlite3` 与 `logs.sqlite3`，否则中止；
3. 把配置库备份到数据目录 `backups/`（见[数据与备份](#数据与备份)）；
4. `requirements.txt` 有变化时，用 `uv pip`（无 uv 时用 `pip`）以 `--require-hashes` 安装依赖；
5. 逐项以同卷原子重命名替换发布包中的顶层条目，任一步失败即全部回滚；`.env`、数据目录、`.venv` 等不在发布包内的文件保持不变；
6. 优雅停机（进行中的请求最多等待 30 秒），再以原始命令行、原始环境变量与工作目录原地重启，进程号不变。

页面实时显示下载字节数、当前步骤与总进度；重启后自动轮询，新版本上线即提示并刷新页面。

- **Git 工作区**：已跟踪文件按发布内容替换，未提交的修改会被覆盖，请先提交或暂存；被替换目录中未跟踪与已忽略的文件（如 `web/node_modules`、`docs/plans`）迁回新目录，HEAD 不移动，之后 `git status` 会显示与当前提交的差异。
- **容器**：程序文件写入容器可写层；镜像层中的目录无法重命名时改为复制后删除，此后的更新又是原子重命名。
- **下载源**：概览中的下载源卡片显示当前使用的源，点击打开抽屉，列出直连 GitHub、内置镜像（ghfast.top、gh-proxy.com、ghproxy.net 等）和一个自定义栏位。可以全部测速，也可以逐个测速（每个源下载最新发布包的前 512 KiB，返回非发布包内容的源判为不可用，不能选用）。自定义栏位填写的前缀使用后会被记住，切换到其他源后仍保留。镜像只用于下载；版本列表仍直连 GitHub API，镜像下载的文件必须与 API 摘要一致，缺少摘要的版本不能经镜像安装。也可用 `CODEBUDDY2API_UPDATE_MIRROR` 设置并锁定。
- **版本核对**：Git 工作区的 HEAD 不是当前版本标签的提交，或有未提交的修改时，页面提示运行的代码可能不是该版本（一键更新后 HEAD 不移动，也会出现此提示）。edge 镜像（构建自 main，记录在镜像内的 `build.json`）会提示原地安装稳定版可能与 edge 已写入的数据不兼容；如需稳定版，请改用 `latest` 或版本号镜像重新部署。
- 「检查更新」每次都会弹出通知：发现新版本、已是最新，或检查失败的原因。
- 早于一键更新功能的版本回滚后需手动升级。

接口：`GET /admin/update`、`POST /admin/update/check`、`POST /admin/update/install`（`{"tag": "v<版本>"}`）、`POST /admin/update/mirror`（`{"mirror": "<前缀或空>", "custom": "<可选，自定义栏位>"}`）、`POST /admin/update/mirrors/test`（可选 `{"mirror": "<前缀或空>"}`，只测一个源）。

## 界面行为

侧栏会记住图标模式。抽屉锁定背景滚动，点击遮罩或按 Esc 关闭并恢复焦点；保存、导入与删除进行中会阻止误触关闭。详情使用带标签的字段与状态分组，原始诊断默认折叠。不支持透明或模糊时，玻璃质感会回退为纯色。

操作结果以浮动通知显示在页面顶部；抽屉打开时显示在抽屉上方。成功的几秒后自动消失，含未完成账号的停留更久。鼠标悬停时暂停计时，点击即关闭；刷新列表或刷新页面会全部清除。任务结束的通知只在看着它运行的页面弹出，刷新页面后不会重复出现。运行中任务的进度横幅仍显示在内容上方。

外观图标提供浅色、深色与跟随系统。四套配色只影响浅色模式；深色固定，浅色偏好保留。语言保存在配置库中，CLI 与所有浏览器共用；其余偏好保留在浏览器本地。抽屉淡入淡出，退出动画期间保持滚动锁定；减少动效的系统设置会跳过动画。

## 模型映射与统计 API

多个独立映射可共用同一上游模型。自定义映射 ID 仅用于管理；客户端使用 `public_id`。账号能力、余额与规避检查照常生效。旧的账号/地域组合范围在编辑时选定明确模式前保持原有交集语义。

- 新建：`POST /admin/models`，携带 `public_id`、`upstream_id` 与范围；编辑：`PUT /admin/models/{id}`；删除：`DELETE /admin/models/{id}`（仅自定义映射）。写操作需携带当前 `revision`。
- 预览：`POST /admin/models/preview` 或 `POST /admin/models/{id}/preview`。`credential_ids` 与 `region`/`profile` 互斥。
- 统计：`GET /admin/dashboard?days=1&granularity=auto`，粒度可选 `auto`、`hour`、`day`。响应标明 `range.granularity`、`range.partial` 与 UTC 分桶，不虚构缺失的小时历史。

## 数据与备份

数据默认位于 `auth/`，Docker 中为 `/data/auth`。本地安装可设置 `CODEBUDDY_AUTH_DIR`；Compose 用 `CODEBUDDY2API_AUTH_PATH` 指定宿主机目录。

| 文件 | 内容 |
|------|------|
| `*.info` | 官方明文凭证；绝不迁移进 SQLite |
| `control.sqlite3` | 网关设置、私有默认 key、模型规则、会话、冷却、积分/领取、用量与目录缓存 |
| `logs.sqlite3` | 请求明细与独立的聚合统计 |
| `media/` + `media.sqlite3` | 生成媒体文件与元数据；按保留时长清理，不进配置备份 |

审计默认保留 30 天明细与 256 MiB 逻辑明细预算，**不是数据库或目录磁盘占用的硬上限**。明细清理与淘汰都保留聚合。SQLite 失败诊断有独立预算，默认 8192 字节。已有文本日志保留原样，不回填为精确统计。

将整个数据目录挂载到可写本地存储，而不是只挂载单个数据库文件；不要在多个网关实例间共享。

复制前停止网关，并复制整个目录，包括数据库、WAL/SHM、凭证及迁移备份；不要只备份 `.info`。控制库包含默认密钥与登录会话，必须妥善保管。

配置备份保存在数据目录 `backups/`，权限为 0600。每份只含在线拷贝的 `data/control.sqlite3` 快照与 `manifest.json`；后者记录备份类型、UTC 时间与网关版本，更新前的备份另记目标版本。备份不含凭证（`*.info`）、程序文件与 `logs.sqlite3`；配置库仍含默认密钥与登录会话，请妥善保管。

- **更新前**：每次一键更新前生成 `update-<旧版本>-to-<新版本>-<UTC 时间>.tar.gz`。
- **手动**：「存储管理 → 配置备份 → 立即备份」生成 `manual-<版本>-<UTC 时间>.tar.gz`。
- **自动**：「自动备份」抽屉可开启定时备份 `auto-<版本>-<UTC 时间>.tar.gz`，并设置间隔（`backup_interval_hours`，默认 24 小时）与上限（`backup_keep`，默认 7 份）。超过上限时只删除最早的自动备份，手动与更新前的备份不会被自动删除。`CODEBUDDY2API_BACKUP_AUTO`、`CODEBUDDY2API_BACKUP_INTERVAL_HOURS`、`CODEBUDDY2API_BACKUP_KEEP` 会锁定对应设置。

列表中的备份可下载或删除。「恢复步骤」给出停机还原方法：需要回到旧版本时，先在「版本更新」页安装 `manifest.json` 记录的版本，再停止网关并拷回 `control.sqlite3`；备份之后产生的设置与状态会丢失。接口：`POST /admin/storage/backups` 创建手动备份；`GET /admin/storage` 返回备份列表与 `backup_schedule`。

旧 JSON 只在首次升级时导入；迁移后的运行状态以 SQLite 为准。回滚须停机并迁回匹配状态，不能用旧 JSON 覆盖新的领取或会话撤销记录，见[升级与数据迁移](deployment.zh-CN.md#升级与数据迁移)。

API key 与地址见[客户端配置](clients.zh-CN.md)。
